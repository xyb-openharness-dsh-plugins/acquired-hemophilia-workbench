# 需求起点

来源：初始化配置。用户、场景和流程是有效的SPEC互动素材；继承会话中已有明确确认，其余不能仅因配置通过校验就当成设计定稿或研究验证。

目标用户：获得性血友病成人患者与家属/照护者；以「出血发作—止血处理—免疫抑制治疗—减量随访」为主线，不覆盖儿童先天血友病。

场景：获得性血友病不是从小得的血友病：它多在成年后突然出现，身上大片瘀斑、肌肉血肿甚至内脏出血，化验单上 aPTT 很长、Ⅷ因子活性很低，还可能有抑制物。止血要用旁路制剂，随后还要吃几个月的激素或免疫抑制剂把抗体压下去。这些资料分散在急诊、血液科、检验科和药房：每次出血用了什么、因子活性和抑制物滴度怎么变、激素从几片减到几片、下次复查查什么，患者自己往往说不清。工作台把这些放回一条时间轴上，只整理、不判断。

核心流程：
1. 打开工作台，先看今天：距上次出血发作多少天、最近一次 aPTT/Ⅷ因子活性/抑制物滴度是多少、正在用什么药、下次复查大概什么时候
2. 记一次出血：从哪天开始、什么部位、当时怎么处理、医生原话怎么说（照抄，不改写）
3. 记一次化验：aPTT、Ⅷ因子活性、抑制物滴度、血红蛋白，带检测方法/单位/机构，跨方法不合并
4. 记一次治疗或调药：止血药与免疫抑制药的药名、剂量、起止日期、医生原话，按「一次调药」折叠
5. 复诊前整理：出血时间线 + 指标趋势 + 用药变化 + 问题清单，装进一页带着去门诊

完成结果：一次门诊前，患者能在同一屏里找到：上次出血是什么时候、这期间 aPTT/Ⅷ因子/抑制物怎么走的、激素或免疫抑制药减到几片、要问医生哪三个问题；全程不出现任何「你这是不是复发/该不该停药」式判断。

初始布局选择：business-first
